# 盲區員空間感知與移動系統（BLIND Navigation & Echolocation v1.0）

本文件對應「BLIND 空間感知與移動系統改版規格 v1.0」：先記錄改版前檢查到的問題與最小修改方案，再說明各模組、關卡資料格式、規則、測試與尚未解決的部分。

## 1. 改版前的檢查結果

| 檢查項目 | 結果 |
| --- | --- |
| 移動與鏡頭 | `client/src/game/controller.ts`。`yaw` 往右轉遞減，前方＝`forwardOf(yaw)`＝`(-sin yaw, -cos yaw)`；面向深處（+z）時右手邊是 -x。伺服器以同一份碰撞資料驗證位置。**沒有問題，不需修改**（只加了測試關卡用的 `setColliders`）。 |
| 盲區員的視覺限制 | `BlindView` 是炭黑底，不載入 3D 場景。回聲後顯示前／左／右／後四條線。 |
| 回聲與音效 | `sonar()` 只有 4 道射線，用 0.1 m 步進取樣；左右用立體聲 pan ±0.9，前後只差 240 Hz 音高，容易前後混淆；斜向的牆、門框、岔路完全偵測不到；沒有材質、沒有殘響、沒有冷卻。 |
| 方向基準 | 環境音是不分方位的 54 Hz 低鳴（直接接到總音量），轉身時聽不出任何差別。唯一隨轉向變化的是 9 m 內「最近設備指引音」——它指向設備，不能告訴玩家自己面向哪裡。 |
| 座標一致性 | 聽者朝向用 `forwardOf(yaw)`，與移動、鏡頭一致（新增的測試以 Web Audio 規格的方位角公式逐步驗證）。但回聲與指引音用 stereo pan，腳步與語音用 HRTF，**兩套方位系統混用**。 |
| 多人同步 | 回聲完全在本機計算，伺服器不知道；無法做「回聲被偵測」這類風險。 |
| 音訊路由 | 回聲、指引、環境音、隊友語音全部接在同一個 master，**無法分開調整音量**。沒有校準、沒有單聲道降級。 |
| 地標 | 除了 R2 的門後聲（謎題線索），每個房間聽起來都一樣。 |

## 2. 最小修改方案（已實作）

不重寫控制器、伺服器的移動驗證、語音路由。改動範圍：

- `client/src/audio/engine.ts`：
  - 在 master 下加 5 條匯流排：`sfx`、`env`、`echo`、`nav`、`voice`，各自獨立音量；隊友說話時壓低 `env`。
  - 加入單聲道模式。
  - 刪除舊的 `sonar()`，改成材質化的回聲音色。
  - 既有音效只是改接到對應的匯流排。
- `shared/src/acoustics.ts`（新增）：聲學資料格式與純函式，伺服器、客戶端、測試共用。
- `client/src/game/blind/`（新增）：四個模組加一個組合類別。
- `server/src/game/echoRisk.ts`（新增）＋ `room.ts`、`manager.ts` 各加一個事件處理：回聲風險區。
- `client/src/game/loop.ts`：建立並更新組合類別；`F`、`V`、`K` 三個按鍵。
- `BlindView`：16 道射線的短暫反射點。
- 設定頁：各類音量、校準、單聲道、設備指引音開關。
- `Scene`：感測器燈號與地上的警示圈。

## 3. 模組

| 模組 | 輸入 | 輸出 |
| --- | --- | --- |
| `SpatialAudioManager`（`blind/spatial.ts`） | 聲源定義（位置、區域、遮蔽規則、聲音），每幀的聽者區域與門的狀態 | Web Audio 節點鏈：聲音 → 低通（遮蔽）→ 遮蔽音量 → HRTF → `env` 匯流排。聽不到的聲源淡出後拆除節點 |
| `BlindOrientationController`（`blind/orientation.ts`） | 每幀的 `yaw` | 轉向提示音（`nav`）；每個房間的參考音（交給 SpatialAudioManager）；`V` 的朝向播報 |
| `EcholocationController`（`blind/echo.ts`） | 位置、朝向、目前的碰撞盒、關卡材質規則、`ECHO_CONFIG` | 反射的空間音（`echo`）、`BlindView` 的短暫顯示、單聲道時的語音摘要；冷卻與干擾狀態 |
| `AcousticLandmarkManager`（`blind/landmarks.ts`） | `level.landmarks`、門的狀態 | 地標聲源（交給 SpatialAudioManager） |
| `EchoRiskMonitor`（`blind/risk.ts`） | 伺服器送來的感測器狀態（測試關卡在本機模擬） | 預警聲；本機判定 `dangerAt()`（只用於測試關卡） |
| `BlindAudioSystem`（`blind/index.ts`） | 關卡資料、是否為盲區員、門的狀態、語音播報函式 | 組合以上模組；`update()`、`pulse()`、`speakHeading()`、`tripped()`、`dispose()` |
| `EchoRiskTracker`（`server/src/game/echoRisk.ts`） | 感測器定義、伺服器時間、伺服器記錄的玩家位置 | 狀態改變事件、偵測結果 |

角色權限：

- **盲區員**：建立完整系統（回聲、方向提示、參考音、地標、預警）。
- **失語員**：聽得見，所以有參考音、地標與預警（都是公開的環境聲音），**沒有**回聲與方向提示。
- **靜默員**：不建立任何音訊（`AudioContext` 根本不存在）。
- 角色改變、離開遊戲、重新開始時，`dispose()` 會移除所有聲源，並重設回聲的冷卻與干擾。
- 隊友語音的路由規則完全沒有改動（只是改接到 `voice` 匯流排）。

## 4. A：方向基準

- **設施方位**（`headingOf`）：0°＝深處（+z）、90°＝右翼（-x）、180°＝入口、270°＝左翼。「右翼／左翼」以面向深處時的左右命名，不會隨玩家轉身而改變。
  - 刻意不用東西南北，避免和 P04 的旋轉方位儀混淆。
- **轉向提示**：每跨過一個 45° 區間發出一聲（不定位，單聲道也有效）：
  - 斜向：很輕的「滴」；
  - 右翼／左翼：中音；
  - 深處：上升雙音；
  - 入口：低音。
  - 傳送或一幀內轉超過 60° 時安靜地重新對齊。
- **`V` 報出朝向**（「面向深處偏左翼」）。
- **參考音（通風口）**：
  - 位置規則固定：每個房間在右翼牆（-x）的高處、離入口那面牆 2.5 m，學會一次就能在每個房間使用。
  - 聲音是 2.9 kHz 附近的細微氣流「呼吸」，約 3 秒一次起伏，音量很低。它與環境底噪（54 Hz）、回聲（短促的嗒／叮／嗡／咚）、語音（人聲頻段）都容易分辨。
  - 遮蔽：只有同一個房間聽得到，隨距離衰減，門開著也不會傳到隔壁。所以不能隔牆追蹤同一個聲源。
  - 測試會檢查每個通風口離任何門、假門、門洞至少 2 m，所以它不會變成找門的提示。
  - R4（無窗迷宮）的每個節點聽起來完全相同，不洩漏方位儀的資訊。
- **校準**：
  - `K` 依序播放左聲道、右聲道、兩邊同時，並用語音說明；設定頁有同樣的三個按鈕。
  - 聽不出左右時勾選單聲道模式：輸出端混成單聲道，轉向提示照常，回聲另外以語音報出前／右／後／左最近的距離。
  - 一般模式不報距離，保留探索與學習。

## 5. B：主動回聲

`ECHO_CONFIG`（`shared/src/acoustics.ts`，可調整）：

| 參數 | 預設 | 說明 |
| --- | --- | --- |
| `rays` | 16 | 平均分布 360°，第 0 道朝正前方 |
| `range` | 8 m | 偵測距離上限 |
| `cooldownMs` | 1100 | 冷卻；冷卻中再按只有一聲很輕的「喀」 |
| `displayMs` | 1800 | 畫面上反射點的持續時間 |
| `baseDelay`／`delayPerMeter` | 0.06 s／0.034 s | 延遲＝基本＋距離×每公尺（真實聲速的差異只有幾毫秒，放大到聽得出來） |
| `falloff` | 0.42 | 音量＝材質音量×0.26／(1＋距離×falloff) |
| `brightHz`／`darken` | 9000／0.55 | 低通＝brightHz／(1＋距離×darken)：越遠越悶 |
| `reverbBase`／`reverbPerMeter` | 0.18 s／0.13 s | 殘響＝基本＋平均自由路徑×每公尺：越開放越長 |

計算：

- `castEcho` 先用 `boxesNear` 篩出範圍內的碰撞盒（正式關卡每次只測十幾個），再用 slab 法求每道射線的第一個交點。
  - 射線遇到第一個實體就停，所以不會穿牆。
  - 開著的門沒有碰撞盒，射線會穿過門洞，打到後面的東西。
- 同樣的位置與朝向永遠得到同樣的結果。

播放：

- 每個反射在反射點上用 HRTF 播放（轉身時方位跟著更新）。
- 材質音色：

  | 材質 | 用在 | 音色 |
  | --- | --- | --- |
  | 混凝土 | 牆 | 寬頻的「嚓」 |
  | 金屬 | 門、假門 | 兩個不和諧泛音的「叮」，比較長 |
  | 設備外殼 | 一般設備 | 方波的「嗡」 |
  | 木頭 | 文件、桌、櫃 | 低沉的「咚」 |

- 沒有反射的方向，在最遠處有一點很弱的空氣聲，所以開口聽起來是「空間延伸出去」，而不只是一片沉默。
- 畫面：每道有反射的射線畫一小段（垂直於射線），上方＝正前方，1.8 秒後完全消失。材質用線條樣式區分（與音色對應）。
- 不畫沒有反射的方向，不累積，不顯示門或出口的標示。

## 6. C：聲學地標

資料在 `CHAPTER1_ACOUSTICS.landmarks`。每個地標有：識別碼、說明、區域、位置、高度、聲音種類、週期、音量、播放條件（`whenDoorOpen`）、遮蔽規則（`audibleFrom`）。

| 識別碼 | 房間 | 聲音 | 遮蔽 |
| --- | --- | --- | --- |
| `r1_ballast` | R1 | 間歇電流聲（日光燈安定器） | 只有本房間 |
| `r2_drip` | R2 | 右翼角落的漏水（1.7 秒一滴） | 只有本房間 |
| `r3_pipe` | R3 | 左翼牆內管線的三連敲擊（7 秒） | 門 d2 開著時，R2 從門洞聽到悶聲 |
| `r5_transformer` | R5 | 變壓器低鳴（98／196 Hz） | 只有本房間 |
| `r6_fan` | R6 | 排風扇 | 只有本房間 |
| `r7_status` | R7 | 狀態提示器的雙響（4.2 秒） | 只有本房間 |
| `r9_rumble` | R9 | 管道低頻震動 | 只有本房間 |
| `r10_core` | R10 | 核心的脈動 | 門 d10 開著時，出口走廊聽到悶聲 |

- R4 刻意沒有地標。
- R8 只有感測器（見第 7 節）。
- 遮蔽規則統一由 `audibility()` 決定：
  - 同一個區域：直接聽到。
  - 列在 `audibleFrom` 的相鄰區域：連接的開口暢通時，從開口位置聽到悶聲（音量 ×0.28、低通 650 Hz）。
  - 其他情況：聽不到。牆壁永遠完全遮蔽。
- 地標只是聲音，不會被轉成任何地圖或畫面標記。
- **謎題整合**：這一版沒有改變任何謎題的答案（以免破壞唯一解與必要性的窮舉測試）。地標的識別碼是穩定的，之後的謎題或 MUTE 的文件可以引用，例如「維修管線在檔案室的左翼牆內」。

## 7. D：回聲風險區

- **位置**：R8 校準實驗室中央天花板的聲學感測器，偵測半徑 3 m。R8 的四個儀表都在範圍外 1.5 m 以上，所以一般探索可以自由使用回聲；穿過房間中央時才需要選擇時機。
- **週期**：
  - 休息 7 秒，其中最後 1.5 秒是預警；
  - 接著警戒 5 秒。
  - 週期以遊戲開始時間為起點，**由伺服器計算**。
- **可學習的預警**：
  - 聽得見的人（同一個房間）：預警時每 0.5 秒一聲上升的啁啾；警戒時快速的滴答；休息時安靜。
  - 看得見的人：天花板燈號（熄滅／琥珀色閃爍／紅色）與地上的警示圈。他們可以告訴盲區員什麼時候安全。
- **偵測**：
  - 盲區員發出回聲時，客戶端送出不帶任何資料的 `echo:pulse`。
  - 伺服器用**自己記錄的位置**與時間判定：在警戒中的感測器範圍內才觸發。
  - 其他角色的脈衝、干擾期間的脈衝、過於頻繁的脈衝都直接忽略。
- **後果（可以挽回）**：
  - 全隊收到警報聲與通知；
  - 盲區員的回聲被干擾 8 秒，按 F 只有雜訊；
  - 不改變任何謎題狀態。
  - 玩家可以等待、移出圈外，或冒險使用。
- **不是答案旁路**：`echo:pulse` 沒有回覆內容，`risk:tripped` 只有感測器識別碼與干擾時間，`risk:state` 只有識別碼、狀態與剩餘時間。

## 8. 關卡資料格式（給關卡設計者）

```ts
// shared/src/acoustics.ts
interface AcousticLevel {
  id: string;
  zones: { id: string; label: string; rect: Rect }[];      // 區域（遮蔽的單位）
  openings: { id; a; b; at: [x, z]; door?: string }[];       // 區域之間的開口；door＝會開關的門
  reference: { zone; pos: [x, z]; y }[];                     // 每個區域的方向參考音
  landmarks: LandmarkDef[];                                   // 聲學地標（見第 6 節的欄位）
  risks: RiskZoneDef[];                                       // 回聲風險區：zone、pos、radius、idleMs、warnMs、armedMs、jamMs
  muffle: { gain: number; cutoff: number };                   // 從開口傳過來的悶聲
  materialOf: (box: Box) => 'concrete' | 'metal' | 'machine' | 'wood';
}
```

- 新增房間或地標時只改資料，不改模組。
- 第一章的資料是 `CHAPTER1_ACOUSTICS`，測試關卡是 `BLIND_LAB`（`shared/src/blindLab.ts`）。
- 新增材質時：在 `MATERIALS` 加一項，並在 `engine.echoVoice` 加對應的音色。
- 單元測試會檢查：
  - 參考音的位置規則（每個房間一個、在房間內、離門與門洞 ≥ 2 m）；
  - 地標在自己的區域內、識別碼不重複；
  - 開口與門的資料一致。

## 9. 測試關卡（`/?preview=blind-lab`）

- 不需要伺服器與隊友。內容：
  - 起點房間；
  - 9 m 走廊；
  - T 字岔路：一邊是死巷，盡頭有木櫃；另一邊是金屬門，岔路中央有感測器；
  - 目標房間，最遠的牆邊有目標設備。
- 使用和正式遊戲相同的 `BlindAudioSystem` 與移動控制器，只換資料。
- `&map=1` 顯示俯視圖，給設計者檢查用；正式遊戲的盲區員永遠看不到。
- `&mono=1` 測試單聲道。

## 10. 測試與驗收

| 規格第九節 | 自動化測試 |
| --- | --- |
| 1. 四個基本方向的聲源方位 | `acoustics.test.ts`：照 Web Audio 規格的方位角公式驗證四個朝向與 200 組隨機位置；`e2e/blind-lab.ts`：在瀏覽器用 `OfflineAudioContext` 實際算繪 HRTF，比較左右聲道能量 |
| 2. 旋轉後同步更新 | 單元：每轉 10° 方位角連續改變；瀏覽器：往右轉 0°→180°，聲源從右經過正前方移到左 |
| 3. 牆面、門框、岔路的一致資訊 | 單元：起點的四個方向距離與材質；同輸入同輸出；轉身後同一面牆換到另一側；走廊盡頭斜前方的射線比兩側長；關門是金屬、開門後打到門後的設備 |
| 4. 距離與牆壁遮蔽 | 單元：近的反射較早、較大聲、較亮；開放空間殘響較長；正式關卡中牆後的設備永遠不會被回報；參考音與地標的遮蔽規則 |
| 5. 地標在不同距離及房間的辨識性 | 單元：遮蔽規則；瀏覽器：只有目前區域的聲源是「直接聽到」，其他區域不建立節點。**實際的辨識度需要真人試玩** |
| 6. 環境音、回聲、語音同時播放 | 瀏覽器：三條匯流排同時有訊號；隊友說話時環境音自動壓低、回聲不受影響、說完後恢復 |
| 7. 失去立體聲 | 瀏覽器：單聲道模式下左右聲道完全相同；轉向提示不依賴左右；回聲另外有語音摘要 |
| 8. 不影響其他角色 | `browser-playthrough.ts`：盲區員有回聲與方向基準、失語員只有環境聲源、靜默員沒有任何音訊系統；靜默員按 F 沒有作用；完整十題通關照常。整合測試：其他角色的 `echo:pulse` 被忽略、客戶端無法謊報位置 |
| 實際遊玩測試關卡 | `e2e/blind-lab.ts` 的自動玩家只讀「聽得到的資訊」：回聲結果、朝向播報、感測器有沒有在響。它不讀自己的座標或地圖，從隨機朝向出發，靠朝向轉到深處，沿走廊前進，在岔路聽到感測器時等待，聽到金屬門的反射後走過去開門，再聽到設備的反射後走過去完成。最近一次：11 次回聲、約 16 秒，全程沒有被偵測 |
| 風險區 | 單元：週期、範圍、區域、干擾、頻率；整合（三個 socket 客戶端）：同步資料含狀態、狀態廣播、警戒中觸發全隊警報、休息中與其他角色不觸發、後果不改變謎題狀態；瀏覽器：預警聽得到、被偵測後干擾、干擾結束後恢復 |

## 11. 已知限制與待真人試玩

- **聲音設計都是依原則選的參數，沒有經過真人試聽**。需要試玩確認：
  - 參考音、地標、回聲的音量比例；
  - 各材質的回聲是否分得出來；
  - 前後混淆的程度（HRTF 在正前方與正後方本來就容易混淆，轉頭可以分辨，但需要確認）；
  - 預警是否夠明顯。
- 回聲的延遲是放大過的「遊戲化」聲納，不是物理模擬；殘響是合成的，不是真的計算反射路徑。
- 單聲道模式無法自動偵測（瀏覽器不知道玩家戴的是什麼），需要玩家自己用校準確認後勾選。
- 風險區只有 R8 一處示範，難度與週期長短需要試玩調整（`RiskZoneDef` 的參數）。
- 既有的「設備指引音」保留，因為謎題流程依賴它，但可以在設定中關掉。關掉之後只靠回聲、地標與隊友找設備，是否太難需要試玩。
- 地標尚未整合進任何謎題的解法。
