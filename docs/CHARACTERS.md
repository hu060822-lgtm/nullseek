# 角色模型與動畫系統

依《角色模型與動畫系統升級規格》分五個階段實作。本文件記錄每個階段的現況、決定與限制。

## 第一階段：現況盤點（升級前）

| 項目 | 現況 | 問題 |
| --- | --- | --- |
| 角色模型 | `client/src/game/Scene.tsx` 的 `Avatar`：約 25 個方塊與圓柱直接拼成的人形，角色差異只有頭上一塊黑色方塊（遮目板、耳罩、口罩） | 正是規格說的「方塊人」；沒有手掌、頸部、鞋子結構；三個角色的剪影幾乎一樣 |
| 骨架 | 沒有。整個人形是一個 `group`，走路時只有上下彈跳 | 沒有任何關節動作 |
| 動畫 | 無；只有「移動中就上下彈跳」 | 移動、停下、轉身都是瞬間切換 |
| 材質 | 共用的 `MeshStandardMaterial`（骨白琺瑯、霧灰、炭黑），平滑著色、無貼圖 | 與 PS1 方向相反（太乾淨、太塑膠） |
| 視角 | 第一人稱；自己的身體不渲染，角色模型只用在「看隊友」 | 動畫主要服務隊友視角（決定：維持第一人稱） |
| 隊友同步 | 伺服器 10 Hz 廣播 `{x, y, z, yaw}`，客戶端指數平滑插值（`game/remote.ts`） | 沒有姿態資訊：看不出隊友蹲下、操作設備、被鎖定 |
| 角色控制器 | `game/controller.ts`：WASD 平移、Shift 跑步、碰撞滑動；伺服器以同一份碰撞資料與速度額度驗證 | 沒有蹲下 |
| 燈光 | 半球光＋三盞跟著房間移動的點光源；沒有即時陰影（只有接觸陰影貼圖）；`NeutralToneMapping` | 平均、明亮，沒有方向感 |
| 霧 | `FogExp2('#C9C8C2', 0.038)`（暖灰） | 不是冷色 |
| 貼圖 | Canvas 程序貼圖 256–640 px，線性取樣、各向異性 4 | 太細緻，與 PS1 方向不符；但銘牌、房號需要保持可讀 |
| 資產載入 | 沒有任何外部模型；全部程式產生 | 需要 GLB 載入、驗證與失敗處理 |
| 部署 | 前端靜態檔由同一個 Node 程序提供（`express.static`，快取 1 小時） | 新增的 GLB 放在 `client/public/models/`，會被 Vite 原樣複製到 `dist/models/` |

### 決定（與使用者確認）
- **整體轉向 PS1 工業恐怖**：角色與環境一起改為冷色、有限光源、方向光與陰影、霧；但燈號、符號、銘牌、房號這些解謎資訊必須保持清楚可讀。
- **維持第一人稱**：角色模型與動畫用於隊友；自己的蹲下以視角高度呈現。
- **蹲下、受傷、死亡**：蹲下＝新增按鍵（C）的外觀姿勢，同步給隊友；受傷＝答錯被設備鎖定時的觸電反應；死亡＝只放在角色資產與預覽頁，遊戲中不觸發。不新增傷害系統。

### 製作工具與品質上限
這個環境沒有建模師與互動式 3D 軟體，但可以用 Blender 的 Python 模組（`bpy`，無介面執行）以程式建模、建立骨架、刷權重、做關鍵影格動畫並匯出 GLB。因此：

- 模型是**程式產生的風格化低多邊形模型**：由放樣（loft）的多邊形截面組成，有明確的關節環、手套、靴子、制服配件與角色裝備。它是一個「刻意的 PS1 風格原型」，**不是**建模師手工雕塑、拓樸與 UV 都經過整理的正式資產。
- 臉部、布料皺摺、手指的細節上限受限於程式建模；動畫是手寫關鍵影格，沒有動作捕捉。
- 為此建立了**正式模型的匯入介面**（見第二階段）：日後由建模師提供的 GLB 只要符合骨骼命名（或提供對照表）就能直接替換，載入失敗時自動退回程式產生的模型。

## 第二階段：角色垂直切片

### 資產（`tools/characters/build_crew.py` → `client/public/models/`）

| 檔案 | 內容 | 大小（gzip 後） |
| --- | --- | --- |
| `crew_blind.glb`／`crew_deaf.glb`／`crew_mute.glb` | 低多邊形蒙皮網格（約 1,550–1,630 三角形）＋骨架；平面法線；13–15 張 8–64 px 貼圖 | 約 210 KB（53–60 KB） |
| `crew_anims.glb` | 共用動畫庫：同一副骨架＋15 個動畫片段（30 fps） | 約 260 KB（68 KB） |
| `manifest.json` | 骨骼清單、必要動畫、各角色模型、正式模型的替換設定（`overrides`） | 2 KB |

重新產生：`pip install bpy==5.2.2`（Python 3.13）後執行 `npm run models`。產出是固定的（沒有亂數種子以外的變化），提交進版本庫；部署時不需要 Blender。

### 模型
- **人體**：骨盆、腰、胸、肩、頸、頭由 8 邊形截面放樣；上臂、前臂、大腿、小腿在關節處有獨立的截面環；手套有手掌、兩組手指與拇指；工作靴有靴筒、腳背、鞋頭、鞋底與鞋跟。
- **制服**：連身工作服、腰帶與扣環、胸前口袋、袖上的反光條、護膝、大腿側袋；左胸識別牌印著角色字母（A／B／C）。
- **五官**：64×64 的臉部貼圖，2×2 像素的眼睛、1 像素的眉與嘴；鼻子是一個小楔形；耳朵是小方塊。
- **材質**：灰藍、暗綠、髒白、混凝土灰；貼圖以 nearest 放大、mipmap 縮小；前端換成不反光的 Lambert 材質（沒有金屬光澤、沒有塑膠高光）。

### 骨架（19 根）
`hips → spine → chest → neck → head`，左右各 `shoulder → upperArm → lowerArm → hand` 與 `upperLeg → lowerLeg → foot`（字尾 `_L`／`_R`）。權重以「每個截面環指定骨骼」的方式分配，關節處兩根骨骼各半；外套下襬依左右位置平滑地分給兩條腿。

### 動畫（`crew_anims.glb`）
| 規格要求 | 片段 | 說明 |
| --- | --- | --- |
| Idle | `Idle`（4 秒循環） | 呼吸幅度小、姿勢略僵直；偶爾慢慢轉一下頭；三個人的呼吸相位不同 |
| Walk／Run | `Walk`（1.2 秒）、`Run`（0.67 秒） | 播放速度依實際速度調整（減少腳底滑動）；骨盆扭轉與胸口反向 |
| StartMoving／StopMoving | `StartMoving`、`StopMoving` | 起步時重心先往前；停下時上身往後、手臂順著慣性往前，再回到站姿 |
| Turn | `Turn`＋程式疊加 | 原地小碎步；**上半身與頭部的延遲跟隨由前端疊加**（依轉身角速度，有上限、會回彈） |
| Crouch | `Crouch`、`CrouchIdle`、`CrouchWalk` | 蹲下時骨盆往後下方移動，雙腳保持在原地；前臂靠在大腿上 |
| Interact | `Interact`（桌面高度 1.0–1.15 m）、`InteractHigh`（牆面 1.25–1.35 m） | 依隊友面前的設備種類選擇，讓手與設備的高度對得上 |
| Inspect | `Inspect`（手拿文件低頭閱讀）、`Observe`（抬頭看牆上的顯示器、手托下巴） | 文件類設備用前者，顯示器／燈號類用後者 |
| Hurt | `Hurt` | 觸電反應：彈開 → 抖動 → 縮起 → 恢復 |
| Death | `Death` | 膝蓋失力 → 跪下 → 往前倒地；**只在預覽頁播放** |

### 前端（`client/src/game/characters/`）
- `assets.ts`：讀取 manifest、載入 GLB、驗證骨骼與動畫、套用 PS1 材質；只保留旋轉軌與 hips 位移軌（讓比例不同的模型也能共用動畫）。所有載入都有快取，三個角色只下載一次。
- `animator.ts`：動畫狀態機（交叉淡入淡出、一次性動畫、遲滯判定避免網路抖動造成走停來回切換）。
- `CrewAvatar.tsx`：每位隊友一個實例。以 `SkeletonUtils.clone` 複製骨架（材質共用、骨架與動畫狀態各自獨立）；位置與朝向完全來自伺服器同步；模型載入失敗時退回備用人形。
- 預覽頁：`/?preview=crew`（`&clip=Walk&t=0.25&role=DEAF&cam=34&sil=1`）。

### 同步（不影響伺服器權威）
| 姿態 | 來源 | 伺服器驗證 |
| --- | --- | --- |
| 位置、朝向、速度 | 原本的 `player:move`（伺服器驗證碰撞與速度）；速度與轉身角速度由客戶端從同步的位置推算 | 不變 |
| 蹲下 | 客戶端 `player:stance { crouch }`（按 C） | 只接受布林值；純外觀，不影響碰撞、互動距離或權限 |
| 操作／觀察 | **伺服器判定**：開啟設備成功時依設備種類設定（文件與顯示器＝觀察，其餘＝操作）；推門是 1.2 秒的短暫操作 | 客戶端只能「結束」（關閉面板）；走開超過 1.2 m 或離線時自動結束；廣播內容不含設備名稱 |
| 受傷 | **伺服器判定**：答錯被設備鎖定時累加 | 客戶端無法觸發 |

自己的蹲下以視角高度（1.6 → 1.08 m）與速度（0.45 倍）呈現；自己答錯被鎖定時視角短暫震動。

### 移動速度的調整
為了讓步行動畫的步頻合理（減少腳底滑動），也配合恐怖遊戲的節奏，步行速度由 3.4 m/s 調為 2.3 m/s、跑步由 5.0 m/s 調為 4.4 m/s（`shared/src/level.ts`、`client/src/game/controller.ts`）。伺服器的速度上限（7 m/s）不變。

## 第三階段：場景整合與環境轉向

- **色彩**：牆上段髒白琺瑯、下段灰藍護牆、混凝土地磚、深灰天花板、冷白燈具；霧與背景是冷黑 `#11171A`（`FogExp2` 0.062：同一個房間內的線索清楚，隔兩間就沒入霧中）。
- **燈光**：目前房間一盞從天花板斜照、會投影的聚光燈（1024 陰影貼圖、PCF 硬陰影），前後房間各一盞不投影的補光，加上偏暗的冷色半球光。牆、設備、角色都會投影。
- **貼圖**：環境貼圖改為 16–48 px 寬的低解析度並以 nearest 放大（牆板 48×128、地磚 32×32、天花板 16×16、紙張 32×40）；**銘牌、房號、門洞標示、符號板維持高解析度與線性取樣**。
- **材質**：全部平面著色、粗糙度 0.85 以上；黃銅與金屬的金屬度降到 0.3–0.35，沒有展示品般的高光。
- **可讀性檢查**（截圖）：R01 符號板、R02 門燈、R04 地標、R09 門標籤與燈號、設備銘牌在新的燈光下都清楚可辨。
- **PS1 後處理的測試結果**：
  - 低解析度算繪（半解析度＋像素放大）：氣氛到位，但正常距離下設備銘牌的文字無法辨識。**決定：做成設定選項（說明 → 設定 →「復古低解析度畫面」），預設關閉。**
  - 頂點抖動、色彩量化：**評估後沒有實作，也沒有實際截圖測試**。理由：頂點抖動會讓門洞與門框邊緣在走動時抖動，影響判斷位置；色彩量化會縮小燈號顏色之間的差異，而燈號是靜默員的線索。若之後想嘗試，應先以同樣的截圖方式檢查這兩點。

## 第四階段：三名角色的差異

三人共用同一套制服、材質語言與製作標準；差異來自裝備與剪影（`/?preview=crew&sil=1` 以純黑剪影檢查，正面、側面、背面與 12 m 外都能分辨）：

| 角色 | 感官裝置 | 剪影 | 配色 |
| --- | --- | --- | --- |
| 盲區員 | 環繞雙眼的厚重感測面罩（前方封死的感測窗）、太陽穴兩側朝外的拾音器、頭頂天線 | 背後的感測背包與桅杆、頭頂天線 | 灰藍工作服 |
| 靜默員 | 厚重但貼頭的耳罩與頭帶 | 及膝的無袖工作外套（下襬外擴、走路時跟著雙腿擺動）、較寬的肩章 | 暗綠工作服＋髒白外套 |
| 失語員 | 封住口鼻的呼吸器、兩個朝前下方的濾罐、通訊封鎖閥、連到胸前單元的導管 | 垂到上臂的短披肩、背後堆疊的兜帽、腰間的文件匣 | 混凝土灰工作服＋暗綠披肩 |

## 第五階段：效能、同步、載入失敗與部署

- **效能**：每個角色約 1,600 三角形、1 個蒙皮網格、19 根骨骼；每個畫面最多兩位隊友。動畫只保留旋轉軌，播放成本很低。陰影只有一張 1024 貼圖。盲區員完全不下載 3D 場景與角色模型。
- **傳輸**：伺服器對 GLB／JS／CSS／JSON 做 gzip（四個 GLB 由 914 KB 降為約 239 KB）；模型快取 1 天，manifest 每次確認（替換正式模型後不必等快取過期）。
- **載入失敗**：
  - 某個角色的模型下載失敗 → 該角色使用備用人形，其他角色不受影響，主控台警告。
  - 動畫庫下載失敗 → 模型仍顯示（靜止姿勢），主控台警告。
  - 正式模型不存在、或缺少骨骼 → 退回程式產生的模型，警告列出缺少的骨骼並提示使用 `boneMap`。
  - 找不到的模型路徑一律回 404（不會回傳網頁內容讓載入器誤判）。
- **正式模型的匯入介面**：在 `client/public/models/manifest.json` 的 `overrides` 指定：
  ```json
  "overrides": {
    "MUTE": {
      "model": "formal/mute.glb",
      "boneMap": { "mixamorig:Hips": "hips", "mixamorig:Spine": "spine" },
      "clipMap": { "Armature|Idle": "Idle" },
      "scale": 1.0,
      "yaw": 0
    }
  }
  ```
  `boneMap` 把外部骨骼名稱對到本專案的 19 根骨骼；`clipMap` 讓外部模型使用自帶的動畫（沒有列出的動畫使用共用動畫庫）。
- **測試**：`server/test/assets.test.ts`（GLB 結構、骨骼、權重、動畫軌、三角形與貼圖預算、檔案大小）、Socket 整合測試（蹲下、操作／觀察、受傷的同步與驗證）、`e2e/character-assets.ts`（六種載入情境，含以 `boneMap` 接上 Mixamo 命名的模型）、完整的三人瀏覽器通關（角色模型全部正常載入）。

### 限制
- 共用動畫只對「靜止姿勢相近」的模型正確：外部模型若是 T-pose、或骨骼的局部座標軸與本專案不同，必須提供自帶的動畫（`clipMap`），或在 Blender 中重新定向（retarget）後再匯出。
- 動畫在無頭 Chromium＋軟體算繪中以截圖逐格檢查過，沒有在真實 GPU 與真人試玩中檢查過手感；腳底滑動在網路延遲較高時仍會出現。
- 隊友的「操作」動作是依面前設備的種類選擇高度，沒有逆向運動學（IK），手不會精確碰到按鈕。
