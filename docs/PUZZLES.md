# 第一章謎題設計（實作版）

依《第一章謎題系統完整實作規格 v1.0》實作十道謎題。本文件記錄**實際實作的資料與線索分配**，以及每一處與規格不同的地方和理由。答案只存在伺服器（`server/src/game/chapter01/`），開發者模式可以查看。

## 0. 共通原則

### 0.1 三人缺一不可
規格的最終目標是「三名玩家真的需要透過不同感官、資訊交換與共同驗證，才能完成每一道謎題」。實作時對每一題做了兩種檢查（`server/test/necessity.test.ts`）：

- **唯一解**：在所有合法候選答案中，只有一個能滿足成功條件。
- **三人必要性**：拿掉任一角色的線索（或該角色才能做的操作）後，剩下的資訊至少還有兩個候選答案，或無法完成必要的操作。

規格原文中有幾題只要兩個人就能解（例如 P01 只靠 DEAF＋MUTE 就能得到 258）。這些題目保留主題、場景、玩法與答案，只調整「線索怎麼分給三個角色」，每一處都列在各題的「與規格的差異」。

### 0.2 失語員什麼都看得到、聽得到
規格寫 MUTE「可以接收正常環境視覺與環境音訊」。如果燈號、聲音放在大家共處的環境裡，失語員一個人就同時擁有 BLIND 與 DEAF 的線索。因此：

- **專屬線索只透過角色授權的通道傳遞**：角色鎖定的設備面板，或伺服器只傳給該角色的 3D 線索資料（例如 P02 的門燈只傳給 DEAF、門後聲音只傳給 BLIND）。其他角色的客戶端根本收不到這些資料。
- 環境裡只有公開資訊（門、機關外觀、迷宮地標等）。

### 0.3 謎題狀態
`locked → active → (ready) → completed`，另有暫時的 `failed`（同步失敗等，幾秒後回到 `active`）。一次只有一題 `active`；完成後開啟通往下一個房間的門。

### 0.4 錯誤回饋三層級
- **操作錯誤**：不合法的操作（權限不符、距離太遠、謎題不在進行中、格式錯誤），不改變任何狀態。
- **答案錯誤**：操作合法但答案不對，給與謎題相符的局部回饋，並有短暫的設備鎖定（1.5 秒起、每次加倍、上限 6 秒，避免暴力窮舉）。
- **協作失敗**：自己的操作正確，但多人條件尚未成立；只說明缺的是「哪一類條件」，不洩漏他人的答案。

### 0.5 防重送
每個 `puzzle:action` 帶 `requestId`。伺服器為每位玩家保留最近 64 個 `requestId` 的結果；重送的請求直接回傳上一次的結果，不會再執行一次（同一個成功請求不會觸發兩次完成）。

## P01 三種語言（入口訊號室）

| 角色 | 線索／操作 |
| --- | --- |
| BLIND | 「訊號發生器組」播放三組音型（依序）：短、長、短接長 |
| DEAF | 「符號燈」依序亮起：○、△、□（3D 燈只在 DEAF 畫面亮起） |
| MUTE | 「協定卡」：音型 × 符號 的 3×3 對照表 |
| 任何人 | 「密碼輸入器」輸入三位數 |

協定卡（列＝音型、欄＝符號）：

| | ○ | △ | □ |
| --- | --- | --- | --- |
| 短 | 2 | 7 | 4 |
| 長 | 9 | 5 | 1 |
| 短接長 | 3 | 6 | 8 |

第 i 位數字＝（第 i 組音型, 第 i 個符號）的交叉格 → **258**。

**與規格的差異**：規格的協定卡是一對一對照（短＝○＝2），只要符號或只要音型就能查出答案，BLIND 或 DEAF 其中一人是多餘的。改成交叉表後，只知道音型或只知道符號，每一位都還有三個候選。

錯誤回饋：不足三位「訊號尚未完整」；三位但錯誤：失敗聲＋指示燈閃一次。不重置，`attemptCount` 累加。

## P02 聽見不存在的門（四門走廊）

| 門 | 聲音（只傳給 BLIND，空間音訊） | 指示燈（只傳給 DEAF） |
| --- | --- | --- |
| A | 連續高頻音 | 白 |
| B | 低頻震動、音高下降 | 白 |
| C | 低頻震動、音高下降 | 紅 |
| D | 低頻震動、固定音高 | 白 |

MUTE「維修文件」：出口的聲源必須有低頻震動、最後一段音高下降、指示燈為白色。**唯一解 B**。

**與規格的差異**：規格中只有 B 有下降音高，BLIND＋MUTE 就能確定、不需要 DEAF；也只有 C 是紅燈。改成 B、C 聲音相同、A／B／D 同為白燈：只靠聲音剩 {B, C}、只靠燈號剩 {A, B, D}，兩者交集才是 B。

操作：在門前按 E 推門（3D 互動）。錯門：低沉的阻擋聲（聽得見的人）＋門把震動（看得見的人）；同一扇門 1.5 秒內重複推只算一次。B 門開啟即完成。

## P03 逆序檔案（檔案室）

| 角色 | 線索／操作 |
| --- | --- |
| BLIND | 「機械敲擊器」：四次間隔不均的敲擊；可以先試聽「位置 1～4」的參考音，辨認每一下來自哪個位置 |
| DEAF | 「符號排列板」：位置 1～4 上的符號（○ △ □ ◇） |
| MUTE | 「檔案規則」：△＝1、○＝2、◇＝3、□＝4；輸入順序必須從最後一個訊號往前排 |
| 任何人 | 「檔案機器」輸入四位數 |

敲擊順序是位置 2→1→4→3 → 符號 △ ○ ◇ □ → 1 2 3 4 → 反向 **4321**。

**與規格的差異**：規格中 DEAF 直接看到符號依序亮起，BLIND 的敲擊不攜帶任何資訊。改成 DEAF 只看得到「位置上的符號」（靜態），**時間順序只存在於 BLIND 聽到的敲擊**。

錯誤：位數不足「序列不完整」；錯誤「卡片被退回」，只清空輸入。

## P04 沒有地圖的房間（無窗迷宮）

迷宮是一個四面各有一個出口（I～IV 號門洞）的方形房間。每到一個節點，房間外觀幾乎相同，但**方位會旋轉**。

| 節點 | 地標（看得見的人） | 回音特徵（只有 BLIND，回音探測器） | 方位（只有 DEAF，方位儀） |
| --- | --- | --- | --- |
| START | 無 | 長回音 | 北＝III、東＝IV、南＝I、西＝II |
| TRIANGLE | 三角形吊燈 | 短回音 | 北＝II、東＝III、南＝IV、西＝I |
| CYLINDER | 懸吊的圓柱 | 連續低頻震動 | 北＝IV、東＝I、南＝II、西＝III |
| SQUARE | 方形地板 | 三次短促敲擊 | 北＝I、東＝II、南＝III、西＝IV |

MUTE「路線規則」：起點往東、三角形往北、圓柱往西、方形往北；**每到一個節點，必須先由盲區員在回音探測器確認回音特徵，門洞才會解鎖**。

路線：START（東＝IV）→ TRIANGLE（北＝II）→ CYLINDER（西＝III）→ SQUARE（北＝I）→ EXIT。

- 走進門洞（3D 觸發）＝選擇出口；伺服器驗證玩家位置、節點是否已確認、門洞與節點圖。
- 錯誤出口一律回到 START（局部重置，路線進度歸零，紀錄保留）；不會軟鎖。
- 換節點時，伺服器把迷宮裡的三人傳送到房間中央。
- 抵達 EXIT 才完成（伺服器驗證節點進入順序，不看座標）。

**與規格的差異**：規格中 DEAF 看得到地標，MUTE 也看得到；MUTE 有路線規則，兩人就能走完，BLIND 只是「確認」。實作把「確認」做成伺服器強制的條件（BLIND 不確認，門洞不開），並加入「方位旋轉」讓 DEAF 的方位儀成為必要資訊。

## P05 失語協定（協定室）

控制台有三個指令槽，每個指令＝（側向, 動作）：

| 角色 | 線索／操作 |
| --- | --- |
| MUTE | 「協定文件」：三段指令（左側開啟 → 等待 → 右側重複）與符號表（○開啟 △關閉 □等待 ◇重複，━左 ┃右）。不能說話，只能用信號器與**標記工具**（指向設備、確認、否決、請求重複、左右、符號） |
| BLIND | 「側向撥桿」：左／中／右（只有 BLIND 能扳） |
| DEAF | 「指令控制台」：動作轉盤（只標示 ○ △ □ ◇，沒有文字）、送出本槽、提交最終序列、全部重置 |
| 聽得見的人 | 送出後的確認音（接受／拒絕不同） |

正解 `[左・開啟, 中・等待, 右・重複]`。送出本槽時，伺服器比對（撥桿, 轉盤）；錯誤只清空未送出的設定，已接受的槽保留。三槽都接受後提交最終序列才完成。只有 MUTE 發出標記或確認訊號不會推進任何狀態。

**與規格的差異**：規格中 DEAF 看得到視覺錯誤狀態、MUTE 也聽得到確認音，BLIND 是多餘的。改成「側向」只能由 BLIND 的撥桿設定，三人都必須實際操作。

## P06 缺失的第七次脈衝（訊號分析室）

| 角色 | 線索 |
| --- | --- |
| BLIND | 「脈衝監聽器」：六個脈衝（長 短 長 短 長 短），等速、聽不出缺口在哪 |
| DEAF | 「時間槽顯示器」：七個槽位，哪些收到脈衝（只看得到「有／無」，看不到值）；第 4 槽無訊號 |
| MUTE | 「校驗文件」：短＝0、長＝1；七個位元中 1 的總數必須為偶數 |
| 任何人 | 「訊號分析儀」輸入七位元 |

1 0 1 □ 0 1 0 → 已知 1 有三個 → 缺失位元＝1 → **1011010**。

**與規格的差異**：規格中 DEAF 的畫面直接顯示六個位元的值，不需要 BLIND。改成 DEAF 只看得到「有沒有收到」。

錯誤：長度不符／校驗失敗／內容不符（三種分開，不透露缺失值），每次清空輸入。

## P07 三秒鐘的真相（中央控制室）

| 控制台 | 操作者 | 正確設定 | 設定所需的線索在誰手上 |
| --- | --- | --- | --- |
| 聲學共振器 | BLIND | 短、短、長 | DEAF 的「節奏閃光器」（視覺） |
| 燈光控制台 | DEAF | 左、中、右 | BLIND 的「定位音箱」（三個音依序從左、中、右傳來） |
| 中央協定盤 | MUTE | 同步模式 | MUTE 的「模式手冊」，但條件需要另外兩人的資訊 |

模式手冊：

| 共振節奏的最後一拍 | 燈序 | 模式 |
| --- | --- | --- |
| 長 | 由左至右 | 同步模式 |
| 長 | 由右至左 | 反向模式 |
| 短 | 由左至右 | 交替模式 |
| 短 | 由右至左 | 單點模式 |

流程：各自設定（伺服器分別驗證，錯誤只影響該控制台）→ 設定正確後按「準備完成」→ 三人都準備好後，MUTE 啟動同步 → 伺服器建立同步輪次（3 秒窗口，以伺服器收到的時間為準；倒數同時以畫面與聲音提示）→ 三人在窗口內各自按下「執行」。

失敗（逾時、窗口內改動設定）：清除本輪與三人的準備狀態，保留已驗證的設定，必須重新準備。過期或屬於舊輪次的操作一律拒絕；同一操作重送不會計算兩次；舊計時器在重置時一律清除。

**與規格的差異**：規格中每個人的設定線索都在自己手上，只有最後的同步需要合作。改成**交叉持有**：每個人要設定的內容都由另一個人感知。

## P08 會說謊的儀器（校準實驗室）

| 儀器 | 顯示（只有 DEAF 看得到讀數） | 聲音（只有 BLIND 聽得到聲紋） |
| --- | --- | --- |
| 壓力計 | 正常 | 間歇震動 |
| 溫度計 | 過高 | 正常運轉聲 |
| 流量計 | 最大值 | 間歇震動 |
| 電壓計 | 正常 | 穩定嗡鳴 |

MUTE「診斷規則」：顯示正常卻出現間歇震動＝指針卡住（故障）；流量計在最大值時本來就會伴隨間歇震動；溫度過高可以是正常環境狀態；穩定嗡鳴代表自檢通過。

任何人都可以對儀器按「校準」。**唯一解：壓力計**。錯誤：短暫自檢後恢復「校準未改善設備狀態」，不會永久破壞。完成後不能再觸發。

**與規格的差異**：規格中只有壓力計有間歇震動，BLIND＋MUTE 就能確定。改成流量計也有間歇震動（並在規則中說明這是正常現象），只靠聲音剩 {壓力計, 流量計}、只靠讀數剩 {壓力計, 電壓計}。

## P09 不曾發生的循環（循環走廊）— 規則由實作補完

規格的四輪資料保留不變：

| 輪次 | 門序（位置 1→4） | 燈號 | 喇叭播放 | 本輪真實音型（下一輪才聽得到） |
| --- | --- | --- | --- | --- |
| 1 | A B C D | 1000 | A（待機音型） | A |
| 2 | C A D B | 0100 | A | B |
| 3 | B D A C | 0010 | B | C |
| 4 | D C B A | 0001 | C | D（從未播放過） |

| 角色 | 線索／操作 |
| --- | --- |
| BLIND | 「迴響喇叭」：本輪播放的音型；「機械開關組」S1～S4（只有 BLIND 能扳） |
| DEAF | 「循環監視器」與門上的標籤（只在 DEAF 畫面出現）：本輪門序與燈號 |
| MUTE | 「循環規則」 |

循環規則（MUTE）：

1. 喇叭播放的永遠是**上一輪**的音型；第一輪沒有上一輪，播放待機音型。
2. 每一輪的真實音型都不同；本輪的真實音型要到下一輪才聽得到。
3. 燈號亮在第 k 位，代表本輪被保留的開關是 Sk。
4. 出口只會出現在「前三輪的真實音型都已確認、而本輪的真實音型從未被播放過」的那一輪。在那一輪：**先扳下本輪被保留的開關，再走進門序排第一位的門**。
5. 其他時候扳開關，會回報「狀態不相容」；走進任何一扇門，走廊都會重新排列並進入下一輪（紀錄不會消失）。

唯一解：第 4 輪扳下 S4，走進位置 1（標籤 D）。伺服器同時驗證：輪次＝4、門序與燈號符合、S4 已在本輪扳下、走進的是標籤 D 的門。第 4 輪走錯門回到第 1 輪（循環），紀錄保留；每位玩家的線索紀錄（Tab）會依輪次自動記下自己感知到的內容。

為什麼三人都必要：辨認「哪一輪是出口輪」需要比較 BLIND 聽到的歷次音型；要扳哪個開關需要 DEAF 的燈號；哪扇門排第一需要 DEAF 的門序；規則只在 MUTE 手上；開關只有 BLIND 能扳。

## P10 NULL：最後的協定（設施核心）

三個階段依序解鎖，伺服器各自驗證。

**第一階段：重建訊號**（答案 **1101001**，三組 110｜10｜01）

| 角色 | 線索 |
| --- | --- |
| BLIND | 「訊號重建器」：長 長 短｜長｜短 長（第二組的第二個脈衝消失，聽不出來） |
| DEAF | 「燈號組」：第一組 ● ● ○、第二組［遮蔽］［無訊號］、第三組 ○ ● |
| MUTE | 「協定總則」：短＝0、長＝1、停頓＝分隔、1 的總數為偶數 |

第二組第一位只有 BLIND 聽得到（長＝1）、第二位缺失的位置只有 DEAF 看得到、補值需要 MUTE 的校驗規則。

**與規格的差異**：規格的固定序列與 P06 完全相同（1011010），與「不是單純重新輸入先前的答案」矛盾，改用新的序列與分組。

**第二階段：時間順序**（答案 開啟 → 等待 → 重複 → 關閉）

| 角色 | 線索 |
| --- | --- |
| BLIND | 四個音的發生順序（可試聽音 1～4 的參考音）：音 3、音 1、音 4、音 2 |
| DEAF | 音階對照燈：音 1＝□、音 2＝△、音 3＝○、音 4＝◇ |
| MUTE | 符號表（與 P05 相同）：○開啟、□等待、◇重複、△關閉 |

伺服器驗證完整的四段順序（不只比對集合）；錯誤時指令退回待排序狀態。

**第三階段：建立共識**

1. 三人各自在自己的核心控制台按「已驗證」（BLIND／DEAF／MUTE 各一台，角色鎖定）。
2. 三人都驗證後，MUTE 在協定盤選擇 `CONSENSUS` → 伺服器建立同步輪次（3 秒）。
   - 選 `EXECUTE`：回報「CONSENSUS REQUIRED」，不執行。
   - 選 `RESET`：再選一次才確認，重置第三階段。
3. 三人在窗口內各按一次「最終確認」。

逾時只清除同步輪次與最終操作，保留前兩階段與「已驗證」。成功在單一伺服器狀態轉換中完成（標記完成、停止計時、鎖定輸入、開啟出口、廣播、第一章結束），即使兩個成功請求幾乎同時抵達也只會觸發一次。

## 開發者模式

只在 `NODE_ENV` 不是 `production`，或設定 `DEBUG_TOOLS=1` 時啟用（`DEBUG_TOOLS=0` 強制關閉）。遊戲中按 `` ` `` 打開開發者面板；關閉時伺服器拒絕所有 `debug:*` 事件，前端也不會顯示面板：

- 目前謎題的正解、狀態與已滿足的條件、同步剩餘時間、玩家與角色
- 最近十筆操作紀錄
- 重置目前謎題、直接完成目前謎題（測試後面的題目用）、重新初始化整個房間

所有謎題使用固定資料（相當於固定種子 `chapter01-v1`），可以完整重現。
