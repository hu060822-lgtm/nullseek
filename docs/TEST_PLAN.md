`server/test/solver.ts` 是共用的「玩家模擬解題器」，只使用各角色真的拿得到的資料解題（不讀伺服器答案），同時被單元測試、Socket 整合測試與瀏覽器 e2e 使用。

最近一次結果：`npm run typecheck` 全部通過；`npm test` 6 個檔案、126 項全部通過；`npm run e2e:blind` 全部通過（回聲視野出現後約 3.6 秒完全消失；只用聲音資訊的自動玩家 11 次回聲、約 70 秒完成測試關卡，聽到感測器預警時等待，沒有被偵測）；`npm run e2e` 全部通過（加入陰影與角色模型後，十道謎題在軟體算繪下共約 9 分鐘）；`npm run e2e:assets` 六種情境全部通過。

### 執行瀏覽器 e2e

```bash
npm run build
NODE_ENV=production PORT=3001 npm start   # 另一個終端機
npx playwright install chromium            # 第一次需要
npm run e2e                                # = tsx e2e/browser-playthrough.ts http://localhost:3001 e2e-shots
```

e2e 會檢查：
- 失語員的大廳沒有「啟用麥克風」；盲區員頁面沒有 `<canvas>`；靜默員與失語員有 3D 場景
- WebRTC 語音實際建立的連線恰為三條允許的邊（靜默員沒有任何接收、失語員沒有任何發送）
- 正式環境前端沒有開發者工具；R01 的符號燈線索只有靜默員收到；失語員按 `G` 標記設備，靜默員看到標記
- 透過面板 UI（可變長度數字格、下拉選單、單選、按鈕）、直接互動（推門）與**真的走進門洞**解完 P01～P10；P07、P10 的三人同步窗口成功；三人都看到結局
- 盲區員有回聲與方向基準、失語員只有環境聲源、靜默員沒有任何音訊系統；盲區員按 F 之前沒有任何畫布、按 F 後只有回聲視野的畫布、沒有下載任何模型；靜默員按 F 沒有作用
- 房主可以帶全隊回到大廳；三個瀏覽器的主控台都沒有錯誤

注意：
- 在沒有 GPU 的環境（SwiftShader）每個 3D 分頁只有約 1～2 FPS，e2e 以直接設定控制器位置的方式走路（位置仍由前端正常送出、由伺服器驗證）。
- e2e 為每位玩家啟動獨立的瀏覽器行程（模擬三台電腦）。

### 角色升級中由測試抓到的問題
- 程式繪製的貼圖被套用兩次 gamma，角色整個變得太暗（截圖檢查抓到）。
- 頭部貼圖的展開方向相反，臉長在後腦（截圖檢查抓到）。
- 靜默員走路時膝蓋穿出外套：下襬正中央沒有分到腿的權重（截圖檢查抓到）。
- 一次性動畫（受傷、起步）開始時，前一個動畫沒有淡出，兩者疊加（程式檢查時發現）。
- 正式模型的骨骼名稱含有保留字元（例如 Mixamo 的 `mixamorig:Hips`）時，三維函式庫載入後會自動改名，導致 `boneMap` 對不上（`e2e:assets` 抓到）。
- 軟體算繪的幀率下降後，e2e 腳本一次送出的位移超過伺服器的防瞬移額度而被拉回（測試腳本的問題，已改成每幀最多走 1.5 m）。

### 這次重構中由測試抓到的問題
- P01 三台發生器之間的停頓長短寫反，三組音型會黏在一起（解題器分不出組數）。
- 隊友離線時三人同步沒有暫停。
- 每次操作都廣播 `device:refresh`，客戶端重新取得面板時蓋掉了「試聽參考音」回傳的畫面（e2e 抓到）。
- 面板按鈕預設會檢查所有輸入欄位：P07 的「執行」、P10 的「已驗證」在欄位未填時會被前端擋下（e2e 抓到，P07 只有 3 秒窗口）。

### 美術審視

用離線預覽（`/?preview=start|room|ending&room=N&role=MUTE&yaw=度`）與三人實際連線的畫面截圖，逐項對照 `docs/ART_DIRECTION.md` 第 9 節的品質判準（每個區域各截一張有 UI、一張無 UI）。

## 2. 手動測試清單（需要真人）

自動化測試無法驗證「好不好玩、聽不聽得清楚」，以下需要三個人、三台電腦、耳機：

- [ ] 三台不同網路（例如家用網路＋手機熱點）語音是否接通；若接不通，設定 TURN 後再試
- [ ] 盲區員只靠聲音能否找到每一個設備（指引音、語音播報、回聲）；關掉設備指引音後是否仍然可行
- [ ] 回聲視野的範圍、顯示時間、冷卻是否剛好：盲區員能順利行動，但仍然需要隊友與聲音
- [ ] 盲區員：先玩 `/?preview=blind-lab`。能否靠轉向提示與參考音知道自己大致面向哪裡；能否用回聲分辨走廊、岔路、門與目標；四種材質的回聲是否分得出來；前後是否混淆
- [ ] 參考音、地標、回聲、隊友語音的音量比例是否合適（設定頁可以分開調整）；地標在不同距離是否仍認得出來
- [ ] R8 聲學感測器：預警是否夠明顯、週期是否太短或太長、看得見的隊友能否及時提醒
- [ ] 沒有耳機（筆電喇叭）時，單聲道模式與語音摘要是否足以行動
- [ ] 機械敲擊在一般耳機上是否能分辨短／長與分組
- [ ] 靜默員確認自己完全沒有聲音（包括瀏覽器分頁的喇叭圖示不應出現）
- [ ] 失語員能否只靠信號器把規則傳達給另外兩人
- [ ] P07／P10 的 3 秒同步窗口在真實網路延遲下是否合理（可用 `SYNC_WINDOW_MS` 調整）
- [ ] 盲區員能否只靠聲音分辨 R02 四扇門後的聲音方位、R04 的四種回音、R07 的左右聲源
- [ ] R04、R09 的門洞傳送是否讓人迷失得「剛好」，而不是覺得遊戲壞了
- [ ] 失語員的標記工具與信號器是否足以傳達 P05 三段指令、P10 的操作表
- [ ] 第一次玩的隊伍完成第一章所需時間、卡關點與提示使用情況
- [ ] Firefox、Safari 的 Web Audio／WebRTC／Pointer Lock 行為
- [ ] 在一般筆電（內顯）上的幀率（陰影＋蒙皮角色）；冷色暗光在不同螢幕上是否仍保有解謎所需的可讀性
- [ ] 隊友的走、跑、停、轉身、蹲下、操作、觀察、受傷動畫在真實網路延遲下是否自然（有沒有走停來回切換、腳底滑動）
- [ ] 三名角色在遊戲中的距離與燈光下，第一眼能不能認出誰是誰
- [ ] 四種空間異常是否讓人起疑、但沒有讓人誤判路線或線索
- [ ] 中途重新整理頁面、關掉分頁再回來、房主離線
